# AICustomerServiceWeb2 - 架构设计文档

## 设计理念

基于 **ReAct (Reasoning + Acting)** 模式，结合反思机制，构建一个清晰、可测试、可扩展的智能Agent系统。

```

             │

    Success?   Retry?
        │         │

                        │
        ┌───────────────┘
        │
        ▼
    Back to Planning
```

## 核心组件详解

### 1. ReActAgent (核心编排器)

**职责**:
- 管理整个 ReAct 循环
- 维护 Agent 状态
- 协调 Planner、Executor、Reflector
- 处理异常和超时

**关键方法**:
```csharp
public class ReActAgent
{
    Task<AgentResponse> ProcessAsync(
        AgentRequest request,
        IStreamWriter? streamWriter = null,
        CancellationToken cancellationToken = default);

    // 内部状态机
    private async Task<AgentResponse> RunStateMachine(
        AgentContext context,
        CancellationToken ct);
}
```

**状态定义**:
```csharp
public enum AgentState
{
    Planning,    // 规划中
    Executing,   // 执行中
    Reflecting,  // 反思中
    Success,     // 成功完成
    Failed,      // 失败
    MaxRetry     // 达到最大重试次数
}
```

### 2. Planner (任务规划器)

**职责**:
- 分析用户意图
- 将复杂任务拆解为执行步骤
- 选择合适的工具
- 生成执行计划

**输入**: 用户请求 + 上下文
**输出**: ExecutionPlan

```csharp
public class ExecutionPlan
{
    public List<PlanStep> Steps { get; set; }
    public string Reasoning { get; set; }  // 规划理由
}

public class PlanStep
{
    public int StepId { get; set; }
    public string Description { get; set; }
    public string ToolName { get; set; }
    public Dictionary<string, object> Parameters { get; set; }
    public List<int> DependsOn { get; set; }  // 依赖的步骤
}
```

**示例**:
```
用户: "查询内部员工数量，并与去年同期对比"

Plan:
  Step 1: 使用 RAGFlowTool 检索 "内部员工" 的定义和历史查询
  Step 2: 使用 SQLTool 查询当前内部员工数量 (depends on Step 1)
  Step 3: 使用 SQLTool 查询去年同期内部员工数量 (depends on Step 1)
  Step 4: 使用 LLM 分析对比结果 (depends on Step 2, 3)
```

### 3. Executor (执行器)

**职责**:
- 按计划执行每个步骤
- 调用具体工具
- 处理工具执行异常
- 记录执行结果

**关键方法**:
```csharp
public class Executor
{
    Task<ExecutionResult> ExecutePlanAsync(
        ExecutionPlan plan,
        AgentContext context,
        IStreamWriter? streamWriter = null,
        CancellationToken ct = default);

    private async Task<StepResult> ExecuteStepAsync(
        PlanStep step,
        Dictionary<int, StepResult> previousResults,
        CancellationToken ct);
}
```

**执行结果**:
```csharp
public class ExecutionResult
{
    public bool Success { get; set; }
    public List<StepResult> StepResults { get; set; }
    public string? ErrorMessage { get; set; }
}

public class StepResult
{
    public int StepId { get; set; }
    public bool Success { get; set; }
    public object? Result { get; set; }
    public string? Error { get; set; }
    public TimeSpan Duration { get; set; }
}
```

### 4. Reflector (反思器)

**职责**:
- 评估执行结果
- 分析失败原因
- 决定是否需要重试
- 提出改进建议

**反思策略**:

```csharp
public class ReflectionResult
{
    public ReflectionDecision Decision { get; set; }
    public string Reasoning { get; set; }
    public ExecutionPlan? AdjustedPlan { get; set; }
    public List<string> Suggestions { get; set; }
}

public enum ReflectionDecision
{
    Success,         // 成功，无需调整
    RetryWithAdjustment,  // 调整计划后重试
    RetryWithSamePlan,    // 使用相同计划重试
    Fail             // 无法继续，失败
}
```

**反思规则**:

1. **工具调用失败** → 分析错误类型
   - 网络错误 → Retry with same plan
   - 参数错误 → Retry with adjusted parameters
   - 权限错误 → Fail

2. **SQL执行失败** → 分析SQL错误
   - 语法错误 → 使用更多上下文重新生成
   - 表不存在 → 重新检索DDL
   - 超时 → 简化查询或添加限制

3. **结果不符合预期** → 分析逻辑
   - 空结果 → 调整查询条件
   - 结果过多 → 添加过滤条件
   - 结果格式错误 → 调整输出格式

### 6. Context Management (上下文管理)

**AgentContext**:
```csharp
public class AgentContext
{
    // 当前状态
    public AgentState State { get; set; }

    // 用户请求
    public AgentRequest Request { get; set; }

    // 执行历史
    public List<ExecutionAttempt> Attempts { get; set; }

    // 当前计划
    public ExecutionPlan? CurrentPlan { get; set; }

    // 记忆存储
    public IMemoryStore Memory { get; set; }

    // 配置
    public AgentConfig Config { get; set; }
}

public class ExecutionAttempt
{
    public int AttemptNumber { get; set; }
    public ExecutionPlan Plan { get; set; }
    public ExecutionResult Result { get; set; }
    public ReflectionResult Reflection { get; set; }
    public DateTime StartTime { get; set; }
    public DateTime EndTime { get; set; }
}
```

**Memory Store** (持久记忆):
```csharp
public interface IMemoryStore
{
    // 保存工具调用结果（用于缓存）
    Task SaveToolResultAsync(
        string toolName,
        Dictionary<string, object> parameters,
        ToolResult result);

    // 获取类似的历史调用
    Task<List<ToolResult>> GetSimilarCallsAsync(
        string toolName,
        Dictionary<string, object> parameters,
        int topK = 3);

    // 保存成功的执行计划（用于学习）
    Task SaveSuccessfulPlanAsync(
        string userIntent,
        ExecutionPlan plan);

    // 获取类似意图的历史计划
    Task<List<ExecutionPlan>> GetSimilarPlansAsync(
        string userIntent,
        int topK = 3);
}
```

### 7. SSE Stream Management

**流式输出结构**:
```csharp
public interface IStreamWriter
{
    Task WriteThoughtAsync(string thought);     // 思考过程
    Task WriteActionAsync(string action);       // 执行动作
    Task WriteObservationAsync(string obs);     // 观察结果
    Task WriteReflectionAsync(string reflect);  // 反思内容
    Task WriteFinalResultAsync(object result);  // 最终结果
}
```

**输出示例**:
```
[Thought] 分析用户问题：需要查询内部员工数量
[Action] 计划执行步骤：
  1. 检索 "内部员工" 定义
  2. 生成SQL查询
  3. 执行查询
[Action] 步骤1: 调用 RAGFlowTool...
[Observation] 检索到 5 条相关信息
[Action] 步骤2: 生成SQL...
[Observation] SQL: SELECT COUNT(*) FROM sys_emp WHERE Type=1...
[Action] 步骤3: 执行查询...
[Observation] 查询结果: 412 人
[Reflection] 执行成功，结果符合预期
[Result] 系统共有 412 名内部员工。
```

## 关键优势

1. **清晰的职责分离**: 每个组件只做一件事
2. **强大的反思机制**: 失败后能自动分析和调整
3. **灵活的工具系统**: 易于添加新工具
4. **完整的可观测性**: 通过SSE实时展示思考过程
5. **高可测试性**: 每个组件都可以独立测试
6. **持久记忆**: 从历史中学习，提升效率
